# OctoAcme Project Management Docs

OctoAcme uses a customer-first, iterative approach to deliver product features, services, and integrations. Projects move through initiation, planning, execution, release, and closeout: teams validate the problem and outcomes, agree on scope and milestones, build and test in increments, deploy and verify changes, then capture learnings and next steps.

The Project Manager coordinates delivery, schedules, risks, and communications. The Product Manager defines outcomes, prioritizes work, and measures success; developers implement and test the work, QA validates acceptance, and stakeholders provide input and approvals. Clear ownership, evidence-based decisions, and psychological safety guide collaboration throughout the lifecycle.

Teams track work on a project board and coordinate through standups, weekly delivery syncs, and sprint or milestone demos. PMs and Product Managers align regularly, stakeholders receive periodic status updates, and risks or blockers are reviewed and escalated through the agreed path. Retrospectives turn lessons from sprints, releases, and incidents into owned improvement actions.

Quality is part of each delivery stage: teams write unit tests for new logic, add integration tests where applicable, and run end-to-end smoke tests for critical flows before release. Pull requests should include issue links and acceptance criteria, pass automated tests, linting, and security scans, and receive the required review. Releases also include a rollback or mitigation plan and post-deployment verification.
